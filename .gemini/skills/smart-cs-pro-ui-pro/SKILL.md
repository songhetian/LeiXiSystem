# 生产力工具全功能守护准则 (Functional Integrity Guard)

## 核心法则：零缩水、全闭环
在进行任何 UI 优化或代码重构时，必须遵守以下操作链路，严禁私自精简功能。

## 第一阶段：修改前审计 (Pre-Modification Audit)
在调用 `write_file` 或 `replace` 之前，必须在内心或日志中列出目标文件现有的**核心功能矩阵**。
*   **交互类**：点击进入、双击编辑、右键菜单、拖拽上传/移动。
*   **业务类**：附件关联逻辑、分页计算、权限校验（公开/私有）、API 真实提交逻辑。
*   **状态类**：Loading 占位、错误捕获、成功提示（Toast）。

## 第二阶段：零缩水执行 (Zero-Simplification Execution)
*   **代码简洁 ≠ 逻辑删除**：优化应体现在组件提取、性能提升上，而非删除业务逻辑。
*   **严禁占位符**：禁止使用 `// ... logic here` 或 `// handle upload` 等注释代替真实的 API 请求代码。
*   **视觉对齐**：在改变颜色或样式时，必须保留其对应的功能触发器（如点击事件）。

## 第三阶段：回归验证 (Regression Verification)
完成修改后，必须对着第一阶段的“功能矩阵”进行逐一检查：
1.  新建/编辑功能是否依然能提交到后端？
2.  附件上传功能是否依然能处理文件流？
3.  批量操作（全选、Shift连选、一键公开）是否依然响应？
4.  右键菜单的所有选项（重命名、删除、权限）是否依然生效？

## 违规红线
- [ ] 优化后分类点击无反应。
- [ ] 优化后原本有的“上传”按钮或逻辑消失。
- [ ] 优化后右键菜单映射错误。
- [ ] 将真实 API 调用改为纯 UI 演示。
