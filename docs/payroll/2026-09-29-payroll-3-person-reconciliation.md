## 一、门槛是什么

step-4 §4.3 完成标准：「抽 3 名员工人工对账一致后方可上线」「宁可慢不可错」。
本门槛验收的是**算薪引擎算得对不对**，不是代码跑不跑得通。

本次落地方式：

- **机算**：`backend/src/payroll/engine/payroll-engine.ts`（真实引擎，零 mock）。
- **人算**：独立手算期望值（公式见第三节），**禁止从引擎结果反抄**——手算值先于验证写下，
  与引擎输出比对，两者一致才算通过。
- **比对工具**：`backend/src/payroll/engine/payroll-reconciliation.ts`（按 code 逐项比对，
  整数分定点运算；单侧缺项 / 员工缺失 / 合计笔误均判不通过）。
- **签字载体**：`formatReconciliationReport()` 生成的人读对账单（第四节）。

## 三、人算公式留痕（手算过程，可独立复核）

统一口径（与 CONTEXT.md / 引擎注释一致）：

- 小时基数 = 基本工资 ÷ 21.75 ÷ 8
- 加班费 = 平日 h×1.5 + 休息日 h×2 + 法定假日 h×3，乘小时基数
- 缺勤扣款 = 基本工资 ÷ 当月应出勤天数 × 缺勤天数（负数）
- 全勤奖 = 无迟到 且 无早退 且 无缺勤 且 无请假
- 迟到/早退扣款 = 次数 × 每次扣款（本次配置 50 元/次）
- 餐补 = 实际出勤天数 × 10 元/天；社保代扣固定 500 元

**员工A**（基本 5000，应出勤 22，实出勤 22，平日加班 10h）：

```
小时基数 = 5000 ÷ 21.75 ÷ 8 ≈ 28.735632
加班费   = 10 × 28.735632 × 1.5 = 431.034483 → 431.03
全勤奖   = 200（无迟到/早退/缺勤/请假）
餐补     = 22 × 10 = 220
社保     = -500
合计     = 5000 + 431.03 + 200 + 220 - 500 = 5351.03
```

**员工B**（基本 6000，应出勤 22，实出勤 20，缺勤 2，迟到 3 次，休息日加班 8h）：

```
小时基数 = 6000 ÷ 21.75 ÷ 8 ≈ 34.482759
加班费   = 8 × 34.482759 × 2 = 551.724138 → 551.72
缺勤扣款 = -(6000 ÷ 22 × 2) = -545.454545 → -545.45
迟到扣款 = -(3 × 50) = -150
全勤奖   = 无（迟到 3 次）
餐补     = 20 × 10 = 200
社保     = -500
合计     = 6000 + 551.72 - 545.45 - 150 + 200 - 500 = 5556.27
```

**员工C**（基本 4000，月中入职应出勤 14，实出勤 11，请假计缺勤 3，早退 1 次）：

```
缺勤扣款 = -(4000 ÷ 14 × 3) = -857.142857 → -857.14
早退扣款 = -(1 × 50) = -50
全勤奖   = 无（有请假、有缺勤）
餐补     = 11 × 10 = 110
社保     = -500
合计     = 4000 - 857.14 - 50 + 110 - 500 = 2702.86
```

舍入口径：单项四舍五入到分后，**合计 = 各项定点累加**（`assertPayrollBalanced` 保证），
不是「先算总账再分摊」。

## 五、真实批次上线时如何复跑（重要）

样例对账证明的是**引擎计算规则正确**；上线门槛的最后一步是**真实数据复跑**：

1. 选定月份，确认该月考勤月报（输入必须是**已确认的月报快照**，ADR-0011）；
2. 从真实 `PayrollRun` 明细构造 `PayrollResult[]`（员工/各项金额）；
3. 由财务/HR **独立手算**同样 3 名（建议抽：1 名满勤、1 名有缺勤/迟到、1 名月中入离职）
   员工的工资，填成 `ManualExpectation[]`（公式沿用第三节）；
4. 调 `reconcilePayroll` 比对 → 通过后打印对账单签字归档；
5. 任何对算薪引擎的后续改动，`tests/payroll-reconciliation.unit.test.ts` 会守住样例基线不回归。
