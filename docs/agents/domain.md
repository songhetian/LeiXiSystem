# 领域文档

工程技能在探索代码库前，如何消费本仓库的领域文档。

## 探索前先读

- 仓库根目录的 **`CONTEXT.md`**（领域上下文、术语表、已确认业务规则）
- 若存在 **`CONTEXT-MAP.md`** 则不读上面的文件，改为按其指向分上下文阅读各 `CONTEXT.md`
- **`docs/adr/`** —— 动手前阅读与本次工作相关的 ADR

当前本仓库为 **single-context** 布局，根目录只有一份 `CONTEXT.md`。

## 文件结构

单上下文仓库（本仓库即是）：

```
/
├── CONTEXT.md
├── docs/adr/           ← 系统级架构决策（当前 14 条，持续追加）
└── src/ (frontend/、backend/)
```

## 使用术语表词汇

输出中凡命名领域概念（issue 标题、重构提案、假设、测试名），必须使用 `CONTEXT.md` 中的术语原词，不要漂移到术语表刻意规避的同义词。

若需要的概念不在术语表里，这是一个信号——要么你在发明项目未使用的语言（应重新考虑），要么存在真实缺口（记入 `/domain-modeling` 处理）。

## 标记 ADR 冲突

若你的输出与现有 ADR 冲突，应明确 surface（显式提出）而非静默覆盖：

> _与 ADR-0012（kkfileview 预览）冲突——但值得重开，因为……_
