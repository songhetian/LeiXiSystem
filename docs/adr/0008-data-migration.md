# ADR-0008: 数据迁移范围与映射策略

- 状态：已接受（Accepted）
- 日期：2026-08-12

## 背景

重构是"新架构从零搭建"，但业务数据（员工、考勤、工资条、报销）不能丢。旧库 150+ 表在 Step 1 删表清理后，**保留数据如何进入新 schema 未定义**。

## 决策

- **迁移范围**：全部员工、全部工资条历史、近 12 个月的考勤（日报/月报/请假/加班/排班）与报销；更早考勤数据归档不迁（legacy 库只读留存）。
- **迁移方式**：Step 1 编写 legacy → 新 schema 的**字段映射脚本**（一次性 Node 脚本，跑在备份库上），迁移前 mysqldump，迁移后抽样对账（员工数、工资条总数、考勤月报行数）。
- 新功能表（punch_logs 等）无历史数据，从零开始。

## 后果

- 正向：上线即有历史可查（工资条永久合规，ADR/E3），算薪对账有历史基准。
- 成本：映射脚本需要逐表核对字段（参考 legacy/database/）；迁移脚本执行一次即弃，不进入运行时。
- 风险：旧库脏数据（孤儿外键、重复工号）需在映射脚本中清洗，发现即记录报告。
