# ADR-0009: 文件上传链路（直传 + 代理混合）

- 状态：已接受（Accepted）
- 日期：2026-08-12

## 背景

REFACTOR_PLAN 3.2 写"文件上传走 multipart"，11.5 UploadImage 写"OSS 直传"，两条路径矛盾，需明确。

## 决策

混合策略：

1. **图片/头像（公开或低敏感）**：前端**直传阿里云 OSS**——后端签发 STS 临时凭证（时效短、限定路径前缀），前端直传 + 回调登记。优势：不占后端带宽、上传快。
2. **附件/凭证（需权限审计）**：走**后端代理转发**——上传到后端 → 后端落 OSS 并登记记录（操作人/用途/元数据），下载时经后端鉴权。

## 后果

- 正向：图片高频小文件不占服务端资源；敏感文件有权限与审计闭环。
- 成本：需要 OSS STS 签发接口 + 前端直传 SDK（ali-oss web）；代理转发需处理大文件流式。
- 约束：OSS 凭据只存在后端（STS 签发端）；bucket 建议按"public-read 的图片目录"与"private 的附件目录"隔离。
