Candidate 01 Strong

审计日志 → 统一 Hook 机制

97 处调用
分散在 11 个文件

每个路由 handler 内部手动调用 writeAuditLog，传参方式不统一（有的不传 beforeData，有的不传 module），难以批量添加 requestId，无法强制执行敏感字段脱敏规则。

Before · 手动散布
// asset.ts
fastify.post('/items', async (req) => {
  const asset = await createAsset(data)
  // ↓ 审计日志手写，分散在每个 handler
  await writeAuditLog(req, {
    action: 'asset_item_create',
    module: 'asset',
    requestData: data,
    responseData: { id: asset.id }
  })
  return asset
})
在 11 个文件中重复 97 次
After · 统一 Hook
// 新插件 auditPlugin.ts
// 注册时注入 auditContext
fastify.post('/items', async (req, reply) => {
  req.auditContext = {
    action: 'asset_item_create',
    module: 'asset'
  }
  const asset = await createAsset(data)
  return asset
})

// 统一 onSend Hook 自动记录
f.addHook('onSend', async (req, reply) => {
  const ctx = req.auditContext
  if (ctx && reply.sent) {
    await writeAuditLog(req, {
      ...ctx,
      beforeData: ctx.beforeData,
      afterData: ctx.afterData,
      requestId: req.id,
    })
  }
})

Benefits

  • ✅ Locality：审计逻辑与业务代码分离，handler 只关注业务
  • ✅ Leverage：一次修改覆盖 97 处，自动获得 requestId、脱敏规则强制
  • ✅ 测试改进：Hook 可 mock，测试不依赖真实 audit 表
  • ⚠️ 需处理：异步操作（setImmediate）、错误路径记录、beforeData 获取时机

通知发送 → 声明式 Hook 自动触发

仅 3/25 文件
其他 22 个路由均有需求

sendNotification 只在 helpdesk / adjustment / lifecycle 中使用。reimbursement、attendance、payroll 等场景同样需要通知但未触发，人工容易遗漏。

Before
import { sendNotification } from '../services/notification'

fastify.post('/approve', async (req) => {
  await reimburseApprove(id)
  // 忘记通知？无法发现
  return { code: 0 }
})
After · 声明式
// 路由元数据声明通知配置
fastify.post('/approve', {
  audit: { action: 'reimburse_approve' },
  notify: {
    recipients: (req, res) => [res.employeeId],
    template: 'reimbursement_approved',
  }
}, async (req, res) => {
  return reimburseApprove(id)
})
