## T30 事故与恢复：Docker 引擎 500（容器未删，虚惊）
- 现象：compose 构建（大体积 pnpm install 拉依赖）进行中，用户报告"容器全被删了"。实际 `docker ps`/`docker info` 全部 `500 Internal Server Error`（dockerDesktopLinuxEngine 管道）。
- **结论：容器一个没删**（ollama/maxkb/postgres/maxkb-db/redis/minio 全部 Up）。compose up 只创建/启动自己定义的服务，从不删除其他容器；500 是 Docker Desktop Linux 引擎故障（构建高资源占用诱发），表现为列表空/界面异常，像"容器没了"。
- 恢复：用户 Docker Desktop 手动 Restart → 引擎恢复，所有容器 restart 策略自启（Up About a minute）。
- **经验**：①用户环境有 6 个常驻容器（ollama/maxkb/postgres/redis/minio），部署构建前先 `docker ps -a` 基线化 ②构建与容器并行时注意引擎资源 ③怀疑"容器被删"先查引擎状态，别慌。
